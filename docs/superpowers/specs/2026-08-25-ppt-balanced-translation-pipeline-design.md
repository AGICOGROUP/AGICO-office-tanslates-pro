# PPT 平衡型翻译流水线设计

## 决策

PowerPoint 格式路由已经独立，但执行流程尚未形成统一流水线。当前由 `ppt_com.ps1`、`pptx_ooxml.py`、清单校验、图片导出和渲染命令临时组合，多次启动 PowerPoint 并重复扫描整份演示文稿。

本次采用方案 B：保留现有 PPT 格式分支，将其升级为一条独立、可恢复、风险驱动的流水线。普通 `.pptx` 优先使用 OOXML；Microsoft PowerPoint 是旧格式转换、复杂对象处理、最终打开验证和 PDF 导出的权威程序。

## 目标

- 将流程固定为：`preflight → inspect → prepare → translate → validate → apply → verify → render → deliver`。
- 一次提取全部文本、位置、保护项、媒体和风险特征。
- 对上下文一致的重复文本执行安全去重，同时保留全部出现位置。
- 标准 `.pptx` 一次 OOXML 写回；复杂文件一次 PowerPoint COM 写回。
- 先执行自动验证，再按风险进行 PowerPoint 官方视觉检查。
- 普通技术 PPT 不默认追求像素级一致，只修复真实的漏字、遮挡、溢出、错位和层级退化。
- 在不降低质量门禁的前提下，使普通 PPT 端到端处理时间降低 30%–60%。

## 非目标

- 不修改 Word、Excel、PDF、图片或 CAD 翻译分支。
- 不重新设计演示文稿，不默认移动图片、箭头、流程线或工程图元素。
- 不把原生文本扁平化为图片。
- 不自动安装、查找、配置或调用 LibreOffice。
- 不在翻译暂停期间保持 PowerPoint COM 进程常驻。
- 不读取历史译稿，除非用户明确要求复用。

## 当前瓶颈

1. 每个 COM 命令单独启动 PowerPoint 并重新打开文件。
2. `extract`、`inventory-nonstandard`、`export-images`、`verify` 和 `render` 重复遍历全部幻灯片。
3. 清单禁止重复文本去重，重复标题、设备名称、页脚和术语产生重复模型任务。
4. COM 写回按目标形状反复线性查找 Shape ID，并在每个段落写回后执行溢出检测。
5. `verify` 对源文件和译文重复执行结构扫描、形状审计和文本提取。
6. 相同图片按出现位置逐个导出、识别和审核，没有按内容哈希复用。
7. 术语表被作为完整文档加载，没有根据本次唯一文本检索相关条目。

## 流水线架构

### `preflight`

- 验证文件签名、扩展名、可读性和加密状态。
- 计算并保存源文件 SHA-256；源文件始终只读。
- 记录目标语言、输出模式和用户质量要求。
- `.ppt` 使用 Microsoft PowerPoint 将不可变工作副本转换为 `.pptx`，验证转换结果后进入后续流程。

### `inspect`

对 `.pptx` OOXML 执行一次扫描，生成：

- 幻灯片、形状、段落、表格单元格、备注、图表、SmartArt、分组对象和媒体清单；
- 所有待翻译文本的稳定位置和上下文；
- 数字、单位、型号、标准号、URL、标识符等保护项；
- 每张幻灯片的风险原因；
- 图片 SHA-256 分组及全部引用位置；
- 快速、复杂或严格路径结论。

存在普通文本框本身不触发复杂路径。只有对象无法由标准 OOXML 安全提取或写回、含待翻译图片文字、图表/SmartArt/特殊嵌入对象、重要分组对象、备注或验证不确定性时才升级。

### `prepare`

生成 schema-v2 翻译清单：

- `occurrences` 保存每个实际文本位置、上下文、保护项和风险信息；
- `translation_units` 保存需要模型翻译的唯一任务；
- `image_groups` 保存唯一图片和所有引用位置；
- `risk_plan` 保存路径等级、风险幻灯片和验证范围。

只有原文、目标语言、对象角色、上下文签名和保护项序列全部一致时，多个位置才可引用同一翻译单元。短词、多义词和上下文不足的文本默认不合并。

### `translate` 与 `validate`

- 根据唯一文本集合检索术语表，只返回精确短语和最长有效匹配。
- 批量填写 `translation_units`，不直接修改演示文稿。
- 验证翻译完整性、术语、保护项、换行、位置覆盖和源语言残留。
- 翻译失败或清单变化不影响已完成的预检与提取结果。

### `apply`

- 快速路径：一次读取 OOXML、一次修改全部目标节点、一次写出新 `.pptx`。
- 复杂路径：复制源文件后，在一次 PowerPoint COM 会话中写入全部译文并保存一次。
- COM 路径按幻灯片一次建立 Shape ID 索引，不按文本位置重复遍历形状集合。
- 同一形状的全部段落写回后只执行一次溢出检测和局部适配。
- 适配顺序为：精简译文、启用换行、微调间距、局部缩小字号、最后才调整文本框。
- 不覆盖源文件，不生成多轮中间演示文稿。

### `verify`

所有任务都执行：

- 源文件哈希复核；
- OOXML/ZIP 完整性和 PowerPoint 正常打开检查；
- 幻灯片、关键形状、关系、媒体和可编辑文本数量检查；
- 翻译位置覆盖、空译文、源语言残留和保护项检查；
- 图片引用、备注、表格、图表和风险对象的特征检查；
- Microsoft PowerPoint 官方 PDF 导出。

检测到修复警告、结构差异、漏翻、保护项变化或无法确认的复杂对象时，停止普通路径并升级严格验证。

### `render`

- 快速路径：只渲染最终 PDF，生成全部幻灯片的低分辨率缩略图总览；风险页高分辨率检查。
- 复杂路径：检查全部修改页和风险页；必要时补充源文件对应页对比。
- 严格路径：源文件与译文全量渲染和逐页对比。
- 修复后只重新渲染受影响幻灯片；新的结构异常会扩大检查范围。

### `deliver`

只有自动验证和规定的视觉检查均通过后才交付一个新文件，并输出简短验证摘要。

## 图片策略

1. 没有图片关系时完全跳过图片流程。
2. 按媒体字节 SHA-256 分组；相同图片只识别和审核一次，但保留全部引用位置。
3. Logo、照片、无源语言文字图片自动保留并记录原因码。
4. 只有确认包含需要翻译文字的图片才进入本地化和覆盖层流程。
5. 无法安全处理的图片进入人工复核，不阻塞无关幻灯片的自动处理。
6. 图片修改继续遵守局部遮罩、零越界像素变化和工程线条保护规则。

## Office 与 LibreOffice 策略

- PowerPoint 是 `.ppt` 转换、最终打开、保存验证和 PDF 导出的权威程序。
- 标准 `.pptx` 在翻译完成前不启动 PowerPoint；最终验证阶段最多启动一次。
- 复杂写回和最终导出应尽量合并在同一 COM 会话；无法合并时分别记录启动原因和耗时。
- 引入 `scripts/office_com_pdf.ps1` 的 PowerPoint 官方导出能力，但不盲目合并其他工作树中的未提交修改。
- PowerPoint 不可用时停止并报告；只有用户明确授权后才允许使用 LibreOffice 后备。

## 状态与恢复

每个任务使用 `work/<source-stem>-<hash-prefix>/job-state.json`，记录：

- 源文件哈希、目标语言、路径等级和输出路径；
- 每个阶段的完成状态和产物哈希；
- 文本出现次数、唯一翻译单元数、图片出现次数和唯一图片数；
- PowerPoint 启动次数、文件打开次数、整稿遍历次数和阶段耗时；
- 风险原因、严格升级原因和需要人工检查的位置。

源文件、目标语言、上游产物或路径配置变化时，使对应阶段及下游阶段失效；其他已验证阶段可以复用。

## 文件边界

- 新增 `formats/ppt/scripts/ppt_pipeline.py`：唯一流水线入口和状态机。
- 新增 `formats/ppt/scripts/inspect_pptx_package.py`：一次 OOXML 提取、风险分类和图片分组。
- 扩展 `formats/ppt/scripts/pptx_ooxml.py`：schema-v2 一次写回与结构复核。
- 收敛 `formats/ppt/scripts/ppt_com.ps1`：仅保留旧格式转换、复杂写回、PowerPoint 验证和必要导出。
- 扩展 `formats/ppt/scripts/resolve_repo_glossary.py`：根据唯一文本返回相关术语。
- 更新 `formats/ppt/scripts/validate_manifest.py`：验证 occurrences、translation_units、图片和风险计划。
- 新增 `formats/ppt/references/pipeline-cli.md`：命令、退出码、状态恢复和产物说明。
- 精简 `formats/ppt/SKILL.md`：只保留路由、阶段、升级条件和质量门禁。

## 测试策略

严格采用先失败测试、再最小实现：

1. 建立普通文本、重复文本、表格、备注、分组对象、图表、重复图片和溢出文本的合成 `.pptx` 测试夹具。
2. 测试一次扫描生成完整位置清单和风险结论。
3. 测试安全去重不丢失任何出现位置，且不同上下文不会误合并。
4. 测试一次 OOXML 写回只修改目标文本节点并保留关系、媒体和对象结构。
5. 测试 COM 写回按幻灯片建立一次形状索引，并在每个形状完成后执行一次适配。
6. 测试图片哈希复用、无文字图片跳过和不确定图片升级。
7. 测试快速、复杂、严格三种渲染计划及异常自动升级。
8. 使用本机 PowerPoint 运行真实文件集成测试，记录阶段耗时和 COM 计数；测试文件和译文不提交仓库。

## 验收标准

- 普通 `.pptx` 在翻译完成后的 PowerPoint 启动次数不超过 1 次。
- 普通路径不预先全量渲染源文件，最终只执行一次官方 PDF 导出。
- 完整文本位置覆盖率为 100%，安全重复文本只产生一个翻译单元。
- 相同图片只执行一次内容识别和审核。
- 普通 `.pptx` 的非模型流水线耗时相对基线降低至少 50%。
- 普通真实 PPT 的端到端总耗时相对基线降低至少 30%。
- 文件打开、源文件哈希、幻灯片结构、保护项、术语、漏翻和可编辑性检查零回退。
- 风险文件能够稳定升级复杂或严格路径，失败后可从最近已验证阶段恢复。

## 分阶段实施

1. 建立基准计数、性能报告和失败测试，不改变生产行为。
2. 实现一次 OOXML 提取、风险分类、图片哈希和状态文件。
3. 实现 schema-v2 清单、安全去重和术语按需检索。
4. 实现快速路径一次写回，并优化复杂路径形状索引和一次适配。
5. 接入 PowerPoint 官方验证、PDF 导出和风险渲染。
6. 更新 Skill 规则，执行完整回归和真实 PPT 基准对比。

每个阶段独立提交；任一阶段发生质量回退时可以单独撤回，不影响其他格式分支。
