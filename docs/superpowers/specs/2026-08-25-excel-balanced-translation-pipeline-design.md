# Excel 平衡型翻译流水线设计

## 目标

在不降低术语、公式、数字、版式和漏翻控制质量的前提下，逐步减少 Excel 翻译中的重复翻译、重复渲染、无效图片审核和任务级临时脚本，提高常见技术设备表、报价表和清单的处理速度、流畅性与可恢复性。

第一轮优化覆盖 `.xlsx` 以及安全转换为 `.xlsx` 后的 `.xls`。`.xlsm`、宏文件和无法可靠转换的旧格式继续使用严格流程。

## 非目标

- 不修改 PDF、Word、PowerPoint 或图片格式的翻译流程。
- 不重写现有路由器、术语表或蓝条双语版式。
- 不以跳过质量门禁换取极限速度。
- 不自动修改公式、数值、型号、标准号、URL 或其他受保护内容。
- 不在第一轮实现宏文件的快速路径。

## 当前问题

1. 当前规则要求每个文本对象独立翻译，并明确禁止重复文本去重。重复表头、单位和设备名称会形成大量相同翻译任务。
2. 翻译前后均要求对每个工作表和打印区域进行完整渲染，普通单语工作簿存在重复视觉检查。
3. 每个图片实例都必须逐张审核并填写原因，Logo、照片、重复图片和无文字图片成本过高。
4. Excel 分支只有格式路由、术语定位和清单校验，没有统一的任务状态与执行流水线。实际任务容易产生一次性脚本、重复打开工作簿和失败后从头处理。

## 设计原则

- 质量底线始终执行；高成本检查依据可观察风险触发。
- 翻译任务可以去重，位置覆盖不能去重。
- 普通流程遇到异常时自动升级严格流程，不带风险继续交付。
- 每次只引入一个可测量改进，并保持现有严格流程可用。
- 使用 `spreadsheets:Spreadsheets` 规定的工作区依赖和 artifact-tool，不引入另一套 Excel 编辑库。

## 流水线

Excel 路由完成后，严格执行以下阶段：

1. `preflight`：校验容器、计算源文件哈希、确定单语或双语模式、识别宏和工作簿风险特征。
2. `inspect`：一次性提取工作表结构、文本位置、公式、合并区域、图片关系和必要的视觉基线。
3. `prepare`：应用术语表、保护数字和标识符、生成位置清单及安全去重后的翻译单元。
4. `translate`：批量填写翻译单元，不直接修改工作簿。
5. `validate`：验证翻译完整性、术语、保护项和位置覆盖。
6. `apply`：在一次工作簿编辑会话中写入全部译文；双语模式在此阶段插入蓝色翻译行并重映射公式。
7. `verify`：比较必须保持不变的结构，执行漏翻、公式、合并区域、双语行和文件可打开检查。
8. `render`：按风险生成最终渲染；发现问题则升级严格检查。
9. `deliver`：输出翻译文件和简短验证摘要。

每个阶段写入 `job-state.json`。阶段完成后记录输入哈希、输出路径、计数和状态；中断后从最后一个已验证阶段继续。源文件、目标语言、输出模式或上游产物哈希变化时，失效对应阶段及其下游阶段。

## 安全去重

清单分为两层：

- `occurrences`：保存每个单元格、批注、文本框、图表标签、页眉和页脚的独立位置，任何位置都不能因去重而消失。
- `translation_units`：保存需要模型翻译的唯一任务，一个翻译单元可以被多个位置引用。

只有同时满足以下条件才复用翻译：

- 原文完全一致，包括有意义的换行和标点。
- 对象类型一致，例如表头与正文不合并。
- 可获得的语境角色一致，例如同一字段、同类列或同类说明区域。
- 术语匹配和保护项集合一致。

短词、多义词、语境不足或不同字段中的相同文字默认分开翻译。去重只减少模型任务，不减少位置清单和写回验证。

## 渲染策略

### 翻译前

- 每个可见工作表生成一次能覆盖实际使用区域的整体预览。
- 不同时渲染同一工作表的完整工作表和每个打印区域。
- 隐藏工作表先做结构与文本检查；只有包含待翻译内容、被改动或影响输出时才渲染。

### 翻译后

- 普通单语文件渲染所有发生文本变化的可见工作表。
- 未变化的工作表不重复渲染。
- 包含合并单元格、图表、图片文字、文字溢出风险或版式调整的工作表进入增强渲染。
- 蓝条双语版会改变行结构和分页，因此继续完整渲染全部打印页。
- 文件修复警告、结构差异、公式错误、漏翻、溢出或异常分页会自动触发严格全量渲染。

## 图片策略

1. 工作簿没有图片关系时，完全跳过图片流程。
2. 按图片内容哈希分组；同一图片出现多次时只检查一次，但保留全部引用位置。
3. 对唯一图片执行快速分类：
   - 无源语言文字、Logo、品牌标识或普通照片：自动保留并写入机器生成的原因码。
   - 明确包含需要翻译的文字：进入本地化处理。
   - 无法可靠判断：进入人工级复核或严格流程。
4. 只有被本地化或判定不确定的图片需要深度视觉验证。
5. 图片被修改的工作表必须执行最终渲染；未修改图片不重复做像素级比较。

## 核心验证与特征验证

所有任务必须执行：

- 源文件哈希和独立输出检查。
- 文件重新打开检查。
- 翻译位置覆盖、空译文和意外源语言检查。
- 术语与保护项检查。
- 公式文本、数值单元格、合并区域和工作表顺序检查。
- 双语模式的上下行配对、非语言数据不重复、公式重映射及蓝条样式检查。

仅在工作簿包含相应特征时执行：

- VBA 字节比较。
- 图表系列和标签深度检查。
- 图片本地化检查。
- 外部链接、数据验证、筛选器和命名区域的专项检查。

## 自动升级严格流程

出现以下任一情况时停止平衡路径并进入严格检查：

- `.xlsm`、检测到 VBA 或旧格式转换无法被可靠证明。
- 工作簿报告修复、损坏、加密、扩展名不匹配或不支持的对象。
- 公式、数值、合并区域、工作表顺序或受保护项发生非预期变化。
- 图片文字无法可靠识别或安全修改。
- 发现文字裁切、重叠、异常分页、漏翻或双语行不完整。
- 任务状态与实际文件哈希不一致。

严格流程保留当前完整结构比较和全量渲染能力，作为安全回退而非默认成本。

## 可执行资源

Excel 分支增加一个统一、可重复运行的 artifact-tool 流水线脚本，负责 `inspect`、`apply`、`verify` 和 `render` 阶段；现有 Python 路由器和清单校验器继续保留。翻译内容仍由 Codex/GPT 写入清单，脚本不自行调用外部翻译服务。

任务只保留一个可执行 `.mjs` 流水线入口和一个状态文件，避免每次生成多套 builder、检查脚本和重复工作目录。详细命令和清单字段放入 Excel 引用文档，`SKILL.md` 只保留阶段、分支条件和质量门禁。

## 测试策略

实施严格遵循 RED-GREEN-REFACTOR：

1. 先添加能证明当前问题的失败测试：重复翻译单元、无图片跳过、图片哈希复用、渲染计划、阶段恢复和严格升级。
2. 每项功能只实现通过对应测试所需的最小改动。
3. 每个阶段通过后运行 Excel 全部测试和根路由测试。
4. 使用本机现有但不提交仓库的真实样例进行基准比较：普通 `.xlsx`、转换后的 `.xls` 蓝条双语表、包含公式与合并区域的复杂表。

测试必须验证真实清单、状态和工作簿行为，不以纯字符串检查代替功能检查。

## 分阶段实施

1. 建立基准计数和失败测试，不改变生产行为。
2. 实现两层清单与安全去重。
3. 实现渲染计划和图片哈希分类。
4. 实现统一流水线入口、阶段状态和断点恢复。
5. 接入核心验证、特征验证和严格升级。
6. 精简 Excel Skill 规则并完成真实文件对比。

每个阶段独立提交，任何阶段出现质量回退时可以单独撤回，不影响其他格式模块。

## 验收标准

- 普通 Excel 样例总耗时相对当前基线降低至少 30%。
- 重复文本的模型翻译任务数等于安全去重后的翻译单元数，所有原始位置仍被写回和验证。
- 无图片工作簿不进入图片深度检查；重复图片只检查一次。
- 普通单语工作簿不再执行前后重复的全量打印页渲染。
- 双语蓝条、公式、数值、型号、合并区域、术语、漏翻和文件可打开检查零回退。
- 风险文件能稳定升级严格流程，失败可从已验证阶段继续。
- 根路由和 Excel 全部自动化测试通过，PDF、Word、PowerPoint 文件无修改。
